# v3.9 — sensor-based hourglass and communication recovery

## Hardware and build

Open `firmware/Hourglass_v39/Hourglass_v39.ino` in Arduino IDE with **Arduino UNO R4 WiFi** selected. Keep `ClockDisplay.h` and `PresetDisplay.h` in the same sketch folder. The recorded hardware build used Arduino Renesas UNO core **1.6.0**. Arduino Wire is used; no third-party sensor/display libraries are required. The publication does not install a core or upload to your board.

| Function | Connections |
| --- | --- |
| Two sand MAX7219 matrices | DIN D11, CLK D13, CS D10; first DOUT to second DIN |
| Four-module time display | DIN D7, CLK D8, CS D9 |
| GY-87 MPU-6050 | Main Wire: SDA A4, SCL A5 |
| Start / pause / resume | Green button D3 to ground, INPUT_PULLUP |
| Reset / settings | Red button D4 to ground, INPUT_PULLUP |
| Active buzzer | D5 controls the existing NPN driver; not a buzzer power pin |

D2 and the old tilt switch are retired. All modules need the appropriate supply and common ground. Verify the particular GY-87 supply/level-shifting circuit and transistor pinout before connecting; the old v3.3 proposal is not a complete v3.9 assembly drawing. Calibration is specific to the recorded assembly: matrix rotations `{2,0}` and sensor +X along M2 toward M1. Check orientation on your own hardware.

## Operation

Six durations: 30 seconds, 1, 2, 3, 5 and 10 minutes; default is one minute. Green starts/pauses/resumes; red resets, with a two-second hold while idle entering settings. The auxiliary display shows setting/countdown and mode letters S/T/R/P/H/E/D. The sensor controls gravity-responsive sand and holds progress near horizontal, face-down/up or during unsuitable motion. Stable inversion restarts the cycle. Start gives one beep; completion gives three beeps with three receiving-chamber flashes.

## Recovery behavior

A failed sample read freezes active time and sand and cancels sound. Bounded retries reopen Wire, attempt bus clearing when possible, identify the MPU, reset it, verify configuration and wait for stable plausible samples. Same-pose recovery preserves progress and deliberate manual pause; it does not replay a start cue. A real stable inversion still follows normal restart behavior. Persistent power/contact/line faults may require physical correction.

`HOURGLASS_RECOVERY_SELF_TEST` defaults to **0**. It must remain 0 for normal use. Historical real-board recovery testing used a separate temporary build with software-induced read failure; this is distinct from reproducing an electrical fault.

## Serial-output limitation

On the recorded R4 WiFi core, Serial uses the ESP bridge UART, not native USB CDC. Telemetry is paced in small chunks and queued, and records may be dropped when busy. This is not a guarantee of a hard timeout inside the vendor UART driver.
